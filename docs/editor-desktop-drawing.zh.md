## 已观察的现象

实际新包的八份桌面截图中，NSTextView 代码区域只有背景与行号；AX 保存完整输入。普通键盘重新输入、焦点及窗口缩放后仍能复现。真实 worker 对多变量及多层嵌套合成样本产生正确的十项统计，无法静态确认的 `happy.x` 保留未知语义。

用户回复「现在没看 App」，因此没有肉眼显示确认。之后读取的同一 PID 45584 窗口已变为英文 YAML 页、编辑器为空，原因未建立；停止自动输入，没有用旧 AX 索引覆盖新状态。原主 App 包保持原字节，不启动第二个 GUI App。

## 独立诊断与隔离实验

CC 原会话 `3ff2aa0c-b5f3-42d5-98bb-0446b2c157eb` 正常结束，阅读指定源码、AX 与三份截图，提出图层绘制、TextKit 兼容及裁剪假设；没有确认根因。DS 收到同一文本材料，优先怀疑截图遗漏；其完整原始回复的内层 JSON 格式无效，原文与解析错误保留，没有转换成正式接受结果。两者都要求进一步绘制证据。这轮是诊断，不是源变更验收。

只读查询 PID 45584 最近 30 分钟的 TextKit／compatibility 日志，无匹配项；这不能证明所有日志级别均没有相关事件。

在 `build/quality-review/editor-desktop-drawing/probe-workspace/` 复制并逐文件核对 321 文件；独立 Swift 构建目录，只共享既有依赖和绝对路径 Rust 产物。主项目源码不改。

第一轮原生测试导出 editor、clip view、scroll view 与 hosting view 的相同局部矩形。五份局部图像都出现代码，深色字形像素均为 3991；实际 `textLayoutManager == nil`，即当前 TextKit 1，编辑器图层有内容、透明度为 1、没有隐藏。没有证据支持默认 TextKit 2 切换为根因。

第二轮新增整页捕获、清空再设置输入及普通原生插入：局部图像仍有代码，整页图像内对应文本矩形却为零个深色字形像素。加入该整页可见性断言后，实际测试失败三处（初始、更新、插入），不是以构建错误替代失败。这是 native `cacheDisplay` 图像，不能标成系统屏幕截图。

单独去掉编辑器裁剪、外层圆角裁剪、页面透明度、开启编辑器图层或停用 scroll view 主动图层，都没有使整页字形检查通过，实验未合入。普通 AppKit 父视图里的系统 NSTextView 与 SourceTextView，带／不带父图层都能正确显示；进一步加入自定义行号栏后，SourceTextView 整页字形消失，局部捕获仍正常。

仅在隔离副本增加几何日志，实际 `drawHashMarksAndLabels` 收到 `rect={{0,0},{360,140}}`，行号栏 `bounds={{0,0},{38,140}}`。既有 `rect.fill()` 越过行号列，覆盖相邻代码。Apple 本机 SDK `NSView.h` 注释明确说明，`clipsToBounds` 在 macOS 14 起默认 NO。日志只记录几何，不记录配置；调试语句随后移除。

最小修复是在 LineNumberRuler 初始化时显式 `clipsToBounds = true`。隔离探索的两个测试转绿：普通滚动容器和整页 SwiftUI 代码均出现实际字形，静态／更新／插入状态对应像素为 3991／3991／5900。已实际查看整页绿色图像，代码显示正确。该证据仍是原生测试渲染，不标成系统屏幕截图。

正式回归精简为两项：行号背景不抹掉邻近代码（含缩放），以及真实 WorkspaceView 的 A/B 代码、替换与原生插入始终可见。先运行未修复源码，两个测试因六处字形为零失败；随后验证最小修复。首次回归草稿还含一个把已更新 Binding 再拼接插入文本的错误期望，该失败原文保留；修正后重新运行 RED，六处失败均来自真正绘制缺陷。
