## 0. 一页定案

### 0.1 这个 App 是什么

一个面向开发者和 SRE 的 **macOS 配置比较小工具**。

用户提供两份 `env.js`，或者两个 Vault 中选定范围的配置，App 按 **对象 → Key → 类型 → Value** 对齐，清楚展示相同、值变化、类型变化、仅 A、仅 B，以及无法确认的地方。

**不要求先整理 Key 顺序，不执行 env.js，不修改原文件，不写回 Vault。**

正常使用流程：

```text
打开 App
    ↓
选择「文件比较」或「Vault 比较」
    ↓
提供 A / B，确认比较对象或路径
    ↓
比较
    ↓
看差异、查看完整值、复制或导出结果
    ↓
关闭
```

### 0.2 强大应该体现在哪里

| 方向 | 要达到的效果 |
| --- | --- |
| 正确性 | 排序不误报，类型不混淆，未知不伪装成相同或缺失 |
| 解析深度 | 正确处理真实 env.js 中受支持的对象、引用、展开与导出关系 |
| 阅读体验 | Key 对齐、长值看得清、嵌套可展开、搜索过滤准确 |
| 安全边界 | 默认无网络；直连 Vault 由用户明确发起且限定为 KV 读取 |
| 稳定性 | 大输入、取消、网络失败、worker 崩溃都有可恢复状态 |
| 界面品质 | 同一套原生 Mac 风格、稳定布局、细腻动效、完整可访问性 |
| 分发 | 用户拿到 `.app`，无需安装开发语言、包管理器或 Vault CLI |
| 工程质量 | 核心、适配器、UI、分发都提供可复现的测试和验收证据 |

开发成本、时间和技术难度不用于降低这些要求。能力做深，不用增加其他产品模块来显得强大。

### 0.3 明确不做

本次不开发：生产巡检、监控、发布、Canary、集群管理、运行时配置采集、服务重启、凭证轮换、Vault 写入、同步、回滚、自动修复、配置迁移、审批平台、日志工具、数据库客户端、请求发送器、通用 JSON/YAML 工具箱、AI 分析、MCP、插件商店、云端账号体系。

也不加入第三种业务模式：**文件 ↔ Vault 的混合比较、多环境矩阵、三方合并**均不在本次范围。

源码预览、搜索、复制、导出、轻量来源档案都只服务于当前这两种比较，不发展成独立平台。

| R11 | 不再建议或增加其他功能 | 所有任务映射到上述两种比较及必要支撑能力 |

### 1.2 本文采用的实现建议，不是用户已确认的技术选择

- 原生 UI：SwiftUI + AppKit。
- 解析与比较核心：Rust；JavaScript 解析基础采用 Oxc。
- Swift/Rust 桥接：先验证 UniFFI；同步、粗粒度接口优先。
- 重计算隔离：随 App 打包、按需运行的 XPC worker。
- Vault：Token 输入；KV v1/v2；仅手动发起的限定范围读取。
- Vault 也可以使用已经取得的 JSON 内容完成离线比较，作为同一功能的低风险输入方式。
- 不需要 App 后端、常驻服务、用户安装的数据库或 JS runtime。

这些选择在 P0 用实际构建验证，而不是假设所有组件直接兼容。

### 1.3 Vault 的安全取舍

“不要高风险的生产平台”不能被理解为“擅自取消最初的 Vault 比较”。因此设计两个输入方式：

| 输入方式 | 用户动作 | App 是否发出 Vault 请求 |
| --- | --- | --- |
| 已有内容 | 导入或粘贴按现有授权流程取得的配置 JSON | 不发出 |
| 手动只读连接 | 输入两侧地址、Token、KV 信息和路径，确认范围后点击读取 | 只发出当前比较所需的受支持读取 |

默认不自动选择真实环境，不恢复后台连接，不定时轮询。只读仍有访问负载、数据暴露和权限风险，不能宣传为零风险。

## 2. 用户如何使用

### 2.1 文件比较

1. 启动 App，默认进入「文件比较」。
2. 左右分别拖入或选择一份 env.js；粘贴 JS 片段是同一个输入区的替代方式。
3. App 解析候选对象，展示 A/B 中的 `devConfig`、`env` 与可解析的最终导出。
4. 默认按同名对象配对；用户确认要比较的对象。
5. 点击「比较」。
6. 默认查看差异和无法比较项；顶部始终保留「全部」入口与完整性提示。
7. 选中字段，在检查器中查看完整值、类型、来源位置与原因。
8. 复制 Key、A 值、B 值或当前差异，必要时导出报告。

把 A 的文件换掉后，只保留仍然有效的对象选择；新结果生成前，旧结果必须标为旧结果，不能悄悄混用。

**比较根契约：** 每次会话每侧选择一个根，一对一配对。对象模式下默认同名配对，允许用户明确选择不同名对象；导出模式下两侧都选择最终导出，不在同一会话混用对象模式与导出模式。比较使用根下的相对分段路径，`env`、`devConfig`、`module.exports` 只是来源标签，不参与字段匹配。例如 A 的 `env.port` 与 B 的 `devConfig.port` 经明确配对后比较的是相对路径 `port`。要看另一个对象，另发起一次比较；不增加多根合并摘要。

### 2.2 Vault 直连比较

1. 进入「Vault 比较」，明确选择「手动只读连接」。
2. A/B 分别输入地址、Token、namespace（需要时）、KV mount 与逻辑路径。
3. 确认目标 mount 是受支持的 KV engine，确认 KV 版本。
4. 默认选择单个 secret；可选择明确路径清单，或者用户主动确认的目录范围。
5. 点「读取并比较」才开始请求；浏览到页面或修改输入框不自动发请求。
6. 读取结果保留每个 secret 的时间、范围与可用版本元数据。
7. 遇到一侧读取失败，保留已读部分，但将总体标为比较不完整。
8. 手动刷新重新取得内容；没有后台轮询。

Token 只用于用户提供的来源，不进入报告、普通日志或 Rust 比较接口。

同一次 Vault 会话两侧使用同一种输入方式：均为手动直连，或者均为离线内容；两侧 KV 版本可以不同。每侧模型仍保存自身输入方式与来源信息，本次不提供直连与离线混搭操作。

### 2.3 Vault 离线内容比较

1. 在同一个 Vault 比较页选择「导入已有内容」。
2. 左右导入 JSON 或粘贴内容。
3. 选择输入类型：纯配置对象、KV v1 响应、KV v2 响应或明确支持的路径映射格式。
4. 预览真正参与比较的数据根；确认包装字段不会误当成配置。
5. 使用完全相同的比较工作区查看结果。

不能因为 JSON 恰好存在 `data.data` 就自动剥掉两层。纯业务配置也可能使用这些名字，必须有明确输入类型或用户确认。

这里的 JSON 支持是为了读取 Vault 内容，不另建通用 JSON 工具模块。导入内容不触发里面的 URL、不使用里面可能出现的认证信息。

**离线输入契约 v1：**

| 显式输入类型 | 参与比较的根 | 校验 |
| --- | --- | --- |
| `plain-object` | 整个配置对象 | 根必须为对象，业务字段 `data.data` 原样保留 |
| `kv-v1-response` | 响应的 `data` 对象 | 包装与数据类型不符则拒绝，不自动换另一种格式 |
| `kv-v2-response` | 响应的 `data.data` 对象 | `data.metadata` 只保留为来源观测；有删除/销毁证据而无内容时按第 6.6 节处理 |
| `path-map` | 每个显式路径对应的配置对象 | 使用下列版本化 schema，不把任意 JSON 猜测为路径映射 |

```json
{
  "schemaVersion": 1,
  "inputType": "path-map",
  "scope": { "kind": "explicit-paths", "paths": ["service/env"] },
  "entries": [
    {
      "path": "service/env",
      "inputType": "plain-object",
      "content": { "PORT": 3000 }
    }
  ]
}
```

映射中的路径为相对 secret 路径，必须唯一；`scope.paths` 与 `entries.path` 一一对应，不允许 `.`、`..` 路径段。条目输入类型仅为上述裸对象、v1 响应或 v2 响应。未提供的路径属于未扫描范围，不因为映射中没有它就判为 secret 不存在；不能从清单推断整个 Vault 目录完整。

JSON 重复 Key 按解码后的精确 Key 检测，包括包装、业务对象及映射；重复则拒绝整个导入文件，提供安全的错误码与位置，不静默采用最后一个值。直连响应采用相同规则，拒绝当前响应，保留其他已经可靠取得的路径。离线导入时间与真实 Vault 读取时间分开，缺少读取时间或版本元数据时明确显示“未知”，不生成虚构来源信息。

### 2.4 看结果的统一方式

结果表四个固定概念：

```text
Key / 完整路径    A 的值    B 的值    状态
```

先回答“有什么不同”，再通过检查器回答“为什么不同”和“原值是什么”。

不显示发布状态、服务健康、环境合规分数或未经观测的运行时结论。

## 3. 功能规格

### 3.1 文件输入与对象选择

| 能力 | 规格 |
| --- | --- |
| 选择文件 | 原生文件选择器；支持空格、中文、长文件名 |
| 拖放 | A/B 独立投放区域；错误类型直接提示，不替换有效输入 |
| 粘贴 | 仅用户主动粘贴；不后台监控剪贴板 |
| 输入保护 | 原文件只读；解析不改格式，不生成旁边的临时副本 |
| 候选对象 | 同名顶层绑定按作用域标识，不靠字符串搜索匹配 |
| 根对象模式 | 比较选定对象；可单独切换最终导出对象模式 |
| 原文定位 | 文件名、真实行列号、定义位置、后续赋值位置 |
| 读取异常 | 文件移动、授权失效、编码不支持、被并发修改均有状态 |
| 输入快照 | 一次比较绑定同一份已读取字节；刷新后使用新 generation |

不扫描整个仓库，不跟随任意 require/import，不搜索用户磁盘。

### 3.2 Vault 输入

| 能力 | 规格 |
| --- | --- |
| 两侧独立配置 | 不假定相同地址、namespace、mount、KV 版本 |
| 认证 | 使用已有 Token；不把账号登录、Token 创建/续期发展成模块 |
| 单 secret | 最短路径；不要求目录列举权限 |
| 多路径 | 用户提供明确清单；按相对路径配对 |
| 目录比较 | 用户显式开启递归，限定根、深度、条目数和请求预算 |
| 差异方向 | Only A / Only B 始终基于当前左右来源 |
| 来源标签 | 显示来源 A/B、地址或本地文件、根路径、读取时间 |
| 轻量档案 | 可明确保存 URL、namespace、mount、path；凭证另行选择是否保存 |
| 离线方式 | 导入已有内容；只对所提供范围作结论 |
| 刷新 | 用户发起；刷新不重置正在阅读的行和过滤条件 |

本次不做 Vault 全量浏览器、策略编辑器、历史版本管理器、复制/同步按钮。

### 3.3 比较阅读能力

| 能力 | 规格 |
| --- | --- |
| 同名 Key 对齐 | 不按源码行数直接比较配置含义 |
| 嵌套结构 | 对象逐层比较；数组保留顺序 |
| 结果视图 | 结构表为主；树状分组与只读源码对照是同一结果的视图 |
| 搜索 | 支持 Key / 路径 / Value；界面可选择搜索范围 |
| 过滤 | 全部、差异、仅 A、仅 B、相同、类型变化、无法比较 |
| 源码对照 | 可查看格式/注释变化，但不把它混入结构差异计数 |
| 长值 | 独立详情、换行开关、水平滚动、完整复制、字符串差异高亮 |
| 显示类型 | Number / String / Boolean 等清楚区分；字符串带引号或显式类型 |
| 显示不可见字符 | 仅作为选中字符串的辅助视图；比较仍以原始值为准 |
| 复制 | Key、A、B、选中差异；复制按钮不修改另一侧 |
| 输出 | 当前比较的 JSON / CSV 报告；有范围和是否包含值的预览 |

不要把“只看差异”实现成隐藏错误。未知与失败必须始终能被注意到。

## 4. 比较语义：统一且可测试

### 4.1 内容比较规则

以下是本产品的默认语义，不宣称任何两个 JS 程序的执行行为完全等价。

| A | B | 结果 |
| --- | --- | --- |
| `{a:1,c:3}` | `{c:3,a:1}` | 相同 |
| `{a:1,b:2,c:3}` | `{c:3,a:1}` | b 仅 A |
| `5000` | `"5000"` | 类型变化 |
| `true` | `"true"` | 类型变化 |
| `1` | `1.0`（同一受支持数值模型） | 数值相同，原字面量仍可查看 |
| `"abc"` | `'abc'` | 解码后的字符串相同 |
| `"abc"` | `"abc "` | 值变化，不自动 trim |
| `null` | Key 不存在 | 不同；null 不是缺失 |
| `undefined` | Key 不存在 | 不同；undefined 是可识别值，不等于不存在 |
| `""` | `null` | 类型变化 |
| `{}` | `[]` | 类型变化 |
| `[1,2]` | `[2,1]` | 按下标比较，值变化 |
| `[undefined]` | 稀疏数组的空槽 | 不同；空槽单独建模 |
| `env["a.b"]` | `env.a.b` | 两条不同路径 |
| 同样的未知函数表达式 | 同样的未知函数表达式 | 无法确认实际值，不标相同 |

对象 Key 默认按解码后的精确字符串匹配；不忽略大小写，不自动做 Unicode 规范化，不根据相似名字匹配。

ECMAScript 本身存在属性枚举顺序规则，因此这里忽略的是配置对象的内容排列，不是承诺依赖枚举顺序的程序行为相同。[S06]

### 4.2 不使用 stringify 代替语义模型

禁止：

```text
JSON.stringify(A) === JSON.stringify(B)
```

作为最终比较算法。

它无法表达本产品要求的来源信息、未解析值、缺失、稀疏数组、JS 特有数值和精度策略。也不允许先用正则把 env.js 改成 JSON 再比较。

### 4.3 数字与字符串

- env.js 的 Number 按受支持的 JavaScript 数值语义处理，保留字面量和必要的精度诊断。
- Vault JSON 数字保留原始数字表示并使用无损解析模型；不先转成 Swift Double 再传给 Rust。
- JS BigInt 独立于 Number；不隐式互转。
- `-0` 与 `+0` 在本产品严格数值模式中区分；NaN、Infinity 等不得变成 JSON null 或普通缺失。
- JS 字符串在核心保留必要的 UTF-16 code unit 信息；不能通过有损编码或显示层的等价判断改变原值。
- 不能将包含 JSON 文本的字符串自动解析成对象来消除差异。
- 超大指数、超长字符串、异常 Unicode 需要资源上限和明确诊断，不静默截断后比较。

具体数值策略版本化写入测试和报告。当前只有文件↔文件与Vault↔Vault，不引入跨来源类型的自动强制转换。

**比较策略 v1 的默认判定：**

| 模型 | 相等规则 |
| --- | --- |
| 已知 JS Number | 按 JS Number 表示的数值比较；正负零不同；NaN 与 NaN 相同；同符号 Infinity 相同；原字面量另存 |
| JS BigInt | 同类型按精确整数比较；与 Number 比较为 TYPE_CHANGED |
| JSON Number | 按无损十进制数值比较，`1`、`1.0`、`1e0` 相同；保留原字面量和零的符号，`-0` 与 `0` 为 VALUE_CHANGED |
| 字符串 | 按解码后的 UTF-16 code unit 序列逐项比较，不采用显示层的 Unicode 等价判断 |

JSON 文本不接受 NaN、Infinity 或 BigInt 字面量。指数、位数、字符串与编码单元预算在 P0 固定版本并记录；超过预算给出 RESOURCE_LIMIT，不转换为浮点近似值，也不静默截断。已知 NaN 的规则不适用于未解析表达式，两边同样写动态调用仍为无法比较。

Swift/Rust/XPC 的字符串 DTO 使用可无损恢复的 UTF-16 编码单元序列，例如 `UInt16` 数组；显示文本是派生预览，不能用 Swift String 的替换字符或规范化结果覆盖原值。JSON Number 的字面量和零符号通过 DTO 保留。报告使用带类型的编码表达这些值，具体 schema 与上限在 P0 定版并以 C12–C14/C21 回归。

### 4.4 五类可比较结果与无法比较

| 结果状态 | 必要条件 |
| --- | --- |
| SAME | 两侧值已可靠取得，并按规则相等 |
| VALUE_CHANGED | 两侧可比较、类型相同、值不同 |
| TYPE_CHANGED | 两侧可比较、类型不同 |
| ONLY_A | A 存在，B 在本次已确认范围内确实缺失 |
| ONLY_B | B 存在，A 在本次已确认范围内确实缺失 |

另有 **NOT_COMPARABLE / 无法比较**，必须带原因：

```text
UNRESOLVED_EXPRESSION
UNKNOWN_OBJECT_IDENTITY
UNSUPPORTED_SEMANTICS
PARSE_ERROR
PERMISSION_DENIED
AUTHENTICATION_FAILED
FETCH_FAILED
UNEXPECTED_RESPONSE
NO_COMPARABLE_CONTENT
PATH_UNCONFIRMED
NOT_SCANNED
RESOURCE_LIMIT
SOURCE_CHANGED
CANCELLED
```

已知的删除状态、销毁状态放在来源观测信息中；不能随意当成空对象。

无法比较原因、稳定操作错误码、来源观测分层建模，不共用一个枚举。关联规则见第 10.6 节；无法建立结果节点的失败也必须有错误码和受影响范围。

### 4.5 缺失和错误不能混淆

**可靠的缺失例子：** 成功解析两份完整对象，A 有 `PORT` 而 B 没有。

**不可靠的缺失例子：** B 的 Vault 请求返回 403 或含义不明的 404。

Vault 的 HTTP API 文档明确说明 404 可能有多种原因，不能仅凭状态码断言对象不存在。[S03]

未知展开可能引入或覆盖任意 Key；这种情况下，受影响对象的缺失判断与完整相同结论必须失效。

### 4.6 范围与计数

- 每个比较会话明确记录选定对象或 Vault 路径范围。
- 同一个结果节点只属于一个终端差异类别。
- 非空且可对齐的对象/数组由子节点计数，父节点只聚合。
- 空对象、空数组必须有可见结果，不从统计中消失。
- 类型变化以该路径为一条差异，不将旧子树和新子树再算一遍。
- 整个子树仅一侧存在时，以根路径计一项；展开只查看内容，不重复增加摘要。
- SAME 的非空对象/数组按同一终端节点规则展开计数，不能随界面折叠状态改变总数。
- 对象模式与导出模式分开统计；不要把 env 和指向同一对象的 module.exports 重复加总。
- Vault 的“secret 数”“配置结果项数”“无法读取路径数”使用不同标签。
- 搜索改变可见数量，不改变扫描完整性的事实。

终端结果项必须满足以下不变量：

```text
结果项总数 = 相同 + 值变化 + 类型变化 + 仅A + 仅B + 无法比较
```

**完整性单独记录，不加入上述加法等式：**

- 已建立且可以定位的终端结果节点归入六类之一；其父聚合节点不重复计数。
- 对象形状未知、目录列举失败、深度/预算阻断、连结果树都无法建立等情况，记录“不完整范围”：来源、相对范围或阻断根、原因、已完成部分。不凭空创建隐藏 Key 或未知 secret。
- 同一阻断范围与同一来源去重，保留原因集合。不得把一个失败重复算为终端结果项；范围记录若覆盖已显示节点，只描述尚不能确认的部分。
- “已知未覆盖路径数”只数实际已知路径；未知子树总量显示“未知”。“不完整范围数”与“未覆盖路径数”分别标注，不宣称前者等于漏读 secret 总数。
- 两侧均为 `{...getConfig(), fixed:1}` 时，`fixed` 可计一项 SAME；未知对象形状另记不完整范围。即使差异 0、无法比较结果项 0，也必须显示比较不完整。

“差异”计数 = VALUE_CHANGED + TYPE_CHANGED + ONLY_A + ONLY_B；NOT_COMPARABLE 独立计数。默认差异视图同时显示四类确定差异和无法比较项，所有过滤下不完整范围提示都保持可见。

只有选定范围完整、不完整范围为 0、四类确定差异为 0、无法比较项为 0，才能显示“全部配置一致”。这些条件适用于已成功建立的比较结果，不能把没有输入或没有可用内容当作空结果通过。

## 5. env.js 解析与静态求值

### 5.1 技术原则

采用：

```text
原始字节
  → 编码校验
  → Oxc AST
  → 作用域和绑定分析
  → 有边界的静态求值
  → 类型化配置树 + 来源位置 + 未解析原因
  → Diff
```

Oxc 提供 JavaScript AST 解析，复杂绑定/语义分析并不都包含在 parser 中；它不是现成的 env.js 配置求值器。需要将 parser、语义分析和本产品自己的静态求值器区分开。[S04]

**App 不调用外部 Node，不 require 用户文件，不 eval，不运行文件里的函数、Shell 或网络请求。**

### 5.2 对象与导出关系

用户原始结构：

```js
var devConfig = {};
var env = {};
module.exports = env;
```

- `devConfig` 和 `env` 独立存在，不自动合并。
- 对象视图显示选定顶层绑定在受支持静态语义下的结果，并明确采用的求值范围。
- 导出视图以最终可确定的 `module.exports` 为根。
- `module.exports` 与 `exports` 的绑定关系不能简化成“搜索最后一个 env 对象”。CommonJS 的导出赋值与别名需要按其语义处理。[S05]

必须覆盖这个反例：

```js
var env = { a: 1 };
module.exports = env;
env = { a: 2 };
```

在可完整确定的这个示例里，env 绑定与导出对象不是同一个最终对象。此项必须是独立回归测试。

### 5.3 计划支持的静态子集

| 层级 | 内容 | 处理 |
| --- | --- | --- |
| A | 字符串、布尔、数字、null、普通对象、数组 | 完整支持 |
| B | var / let / const、已知同文件绑定、属性简写 | 按作用域解析；缺绑定不能瞎补值 |
| C | 已知嵌套引用、已知计算 Key、对象/数组展开 | 按源码顺序和覆盖关系求值 |
| D | 已知模板字符串、白名单运算、可确定条件 | 明确操作符语义，测试通过后启用 |
| E | 受支持的属性赋值、delete、重绑定、导出赋值 | 维护对象身份、别名和修改顺序 |
| F | 动态函数、运行时环境变量、外部 import/require、getter、未知反射 | 不执行，报告未解析和受影响范围 |

“能 parse”不代表“能静态求出值”。支持矩阵必须随版本发布，不能对任意 JavaScript 声称百分之百解析出运行结果。

### 5.4 关键边界样例

```js
var env = { a, b, c };
```

只有同作用域内 `a/b/c` 绑定可确定，才能拿到它们的值。用户用 `{a,b,c}` 描述 Key 排列，不代表真实 JS 中这些值可以凭空生成。

```js
var env = { ...devConfig, PORT: 3000 };
```

只有展开来源及覆盖顺序可确定时才得到最终值。

```js
var env = { TOKEN: process.env.API_TOKEN };
```

不读取 App 当前 Mac 的环境变量冒充 A 或 B 的目标环境。保留表达式，标明运行时值未解析。

```js
var env = { a: 1 };
mutate(env);
```

未知调用可能改变对象。需要使受影响对象或字段进入未知状态，而不是拿调用之前的值当最终值。

```js
var env = { ...getConfig(), fixed: 1 };
```

不能把未知展开忽略。允许保留能证明的后续覆盖值，但整个对象形状仍不完整，不能断言缺失字段。

### 5.5 解析安全和保守性

- 语法错误不能通过“修一下再当原文件解析”来伪造成功。
- 重复 Key 显示定义位置；对于受支持的普通数据属性，按语言覆盖顺序处理。
- `__proto__` 特殊语法、getter/setter、对象原型、Symbol Key 不得按普通 JSON 偷偷处理；未支持时明确诊断。
- 未知调用、逃逸引用、未知条件、异常终止应保守传播不确定性。
- 根级执行完整性无法确认时，允许只读展示源码，但不能给出“最终导出完全相同”。
- 不打开由源码指定的外部文件，不沿符号链接遍历项目。
- 不把未初始化绑定、undefined 和缺失 Key 合为同一状态。
- AST 的定位坐标与界面文本坐标需正确转换，覆盖中文、emoji、多字节字符和不同换行。

**对象身份与未知传播契约：**

- 绑定指向对象身份；属性写入、别名和 `module.exports` 保存的对象引用按源码顺序跟踪。重绑定不自动改变先前导出对象。
- 未知条件产生多个可能身份时，在分支合并中保留可能身份集合。只有在所有可能路径均可证明同一字段、同一值且没有受影响的后续操作时，该字段才保持 Known；否则记录 UNKNOWN_OBJECT_IDENTITY 或 UNRESOLVED_EXPRESSION。
- 对逃逸到未知调用的对象，标记其可能受影响的值和形状；不保留调用前的值冒充最终值。无法约束调用的其他潜在影响时，将相关根或根级执行完整性标为未知。
- 后续确定赋值只在接收对象身份与写入语义可以证明时恢复对应字段。未逃逸的新对象可以保留已知值；未知展开后的确定覆盖可保留该字段，但不恢复整个对象形状完整性。
- 导出根与绑定根分别判断完整性；某次写入影响哪个对象不能确认时，不把它同时当作两个根的确定结果，也不据此判断缺失。

合成回归包括：`var env={a:1}; module.exports=env; if(flag){env=other;} env.B=2;`。`flag`、`other` 未知时，不能断言导出对象一定有 `B:2`。还需验证未知调用后重绑到未逃逸的新对象可恢复该新根的确定值；不能用“一律丢弃所有后续写入”代替身份分析。

### 5.6 资源保护

为文件字节数、AST 深度、节点数、求值步骤、字符串长度、内存、单任务时间设可见限制。

超限时取消或停止该部分，显示限制与影响范围；不把截断结果标为完整。

可取消检查必须进入解析、求值、比较、排序和搜索循环，不只在 UI 按钮上显示取消。

## 6. Vault 比较实现

### 6.1 来源字段

```text
标签
Vault 地址
namespace（可选）
Token（只输入已有 Token）
KV mount
KV 版本
逻辑 path / 明确的 path 清单 / 经确认的目录根
输入方式：直连 / 导入已有内容
```

UI 明确区分 Vault 服务地址、浏览器 UI 地址、mount 和逻辑 path。用户粘贴网页路径时给出可确认的拆解预览，不盲目把整段浏览器地址拿去请求。

namespace 和 Token 使用官方定义的请求机制；具体 namespace 支持取决于目标部署，不假定所有 Vault 都有相同配置。[S03]

### 6.2 KV v1/v2 路由

以下为实现依据，实际请求统一加 API 前缀并按段安全编码：[S01][S02]

| 类型 | 读取配置 | 列举目录 |
| --- | --- | --- |
| KV v1 | `GET /v1/<mount>/<path>` | `LIST /v1/<mount>/<directory>` |
| KV v2 | `GET /v1/<mount>/data/<path>` | `LIST /v1/<mount>/metadata/<directory>` |

读取 KV v2 响应时，仅业务 data 进入配置树；metadata 放在来源信息中，不默认参与字段比较。

`GET ?list=true` 是官方提供的列举替代方式，可用于明确支持的代理兼容策略；它仍然是列举，不是自动绕过权限。[S03]

### 6.3 为什么不能只允许 GET 就算安全

Vault 某些 engine 的 GET 接口会生成动态凭证。因此网络层必须限制 **engine 类型 + 具体路由 + HTTP 操作 + 确认范围**，而不只是禁用 POST。[S07]

实现策略：

1. 对用户选定路径做定向 mount 识别，不枚举所有 mount。
2. 可使用受支持的单 mount 详情接口确认类型与 KV 版本。
3. 该内部接口不保证向后兼容，必须进行版本适配与测试，不能把失败解释为“没有配置”。[S08]
4. 无法可靠确认 KV 类型时，默认停止直连读取，不靠猜测反复 GET；可用已有内容完成比较。
5. 用户手填的 KV 标签不是服务端类型证明。需要额外部署适配时在 P0 明确，不要求 root Token。
6. 服务器可在识别后被重新配置，因此仍不能承诺绝对无副作用；记录识别依据、缩短有效期、刷新时重新核对。

在用户真实环境确认前，不宣称自动兼容所有 Vault 和代理组合。

### 6.4 网络请求白名单

产品代码中只暴露类型化操作：

```text
IdentifySelectedKvMount
ReadSelectedKvSecret
ListConfirmedKvDirectory
ReadSelectedKvMetadata（仅用于当前读取状态解释）
```

没有通用“输入任意 URL 并执行”的网络命令，没有 Vault write/delete/patch/rollback/renew/unseal 调用。

系统级 mount 查询仅限已选择的路径。不要为了连接状态加健康巡检、权限矩阵或诊断平台。

### 6.5 权限和目录比较

- 单 secret 读取不强制先列目录。
- KV v2 列举需要 metadata 路径上的 list 能力。[S01]
- 列出的路径不意味着当前身份一定有对应读取权限。
- 只比较确认范围内的相对路径。例如 A=`app/cp`、B=`app/np`，将两者根下同名相对路径配对。
- 目录标记与 secret 路径独立表示；类似 `foo` 与 `foo/` 不合并成同一个来源。
- 某子目录列举失败时，该子树是未知，不把未读到的内容判为不存在。
- 无 list 权限可使用明确路径清单，但整体只对清单内已确认部分负责。
- 递归请求带最大深度、最大 secret 数和总请求预算；达到边界明确显示“范围未完成”。

### 6.6 错误与缺失的处理

| 来源观测 | UI 行为 |
| --- | --- |
| 成功读取完整对象 | 进行字段比较 |
| 403 | 显示当前请求无权访问，不推断字段缺失 |
| 404 | 结合已确认 mount、路由、版本和响应判读；不足则无法确认 |
| 证据表明 soft-deleted / destroyed | 显示来源状态，不变成空配置 |
| 网络超时或 TLS 失败 | 保留另一侧及此前结果，标明未完成 |
| Token 失效 | 停止新请求，要求用户更新凭证；不自动续期 |
| 返回网页/登录页而非预期响应 | 标明响应类型不符，不作为配置对象解析 |
| 内容超过限制 | 标明未取得完整内容，不比较截断后的值 |

**secret 层的结果契约：** 使用与字段层相同的六类结果状态，但 `DiffRecord.level` 区分 `Secret` 与 `Field`。两侧有可靠配置对象时，secret 节点聚合字段结果；可靠证据确认整条 secret 仅一侧存在时，在 secret 根计一项 ONLY，展开不重复计数。已软删除或销毁的 secret 仍有来源状态，不能等同于路径缺失；缺少可比较内容时，以 NO_COMPARABLE_CONTENT 记录无法比较。`data:null` 本身不证明删除或缺失，缺少状态证据时按响应不符或内容不可用处理。

目录列举只对该次可靠、完整覆盖的范围提供路径存在依据，仍受第 6.7 节时间一致性限制。单 secret 的歧义 404、失败列举、未导入路径均不满足可靠缺失条件。某 secret 已发现但读不到时可建立一项 secret 级无法比较；整个未发现子树被阻断时只记录不完整范围，不伪造其中的 secret 节点。

mount 识别失败时停止该侧后续配置读取；已有另一侧或其他路径内容则总体 Partial，无任何可用比较内容则 Failed，并显示 PATH_UNCONFIRMED 及对应错误码，不解释成“没有差异”。

### 6.7 比较一致性

多个 secret 的串行或并发读取不是全局同一时刻的快照。

会话记录：开始/结束时间、每个来源的读取时间、可用的 KV v2 版本、选定范围、失败路径、解析器/比较策略版本。

同一次比较使用不可变的已读内容；不边展示边偷偷换值。可在本次请求范围内进行可取消的版本复查；检测到变化则标为来源变化，需要用户刷新，不能声称原子一致。

KV v1 无相同的版本信息时，如实说明保证更弱，不伪造版本号。

### 6.8 请求预算与隐私

建议初始默认值，P0 后按受支持部署验证：

| 参数 | 建议初始值 |
| --- | --- |
| 默认范围 | 每侧一个 secret |
| 并发读取 | 每侧最多 2 个在途请求 |
| 限速 | 每侧初始最多约 2 请求/秒，可降低 |
| 读取重试 | 可重试临时错误最多额外 2 次，带退避与抖动 |
| 单请求等待 | 初始 15 秒，允许在明确范围内调整 |
| 递归预算 | 开始前显示；超限暂停，不自动无限扫描 |
| 自动重连/轮询 | 关闭，不提供默认后台任务 |

429、503 等按具体端点语义处理，不所有状态码都盲目重试。取消后不继续排队发新请求。

只向用户确认的目标发送凭证。跨源重定向默认拒绝；同源重定向也必须保持在许可的端点与路径内。TLS 验证不能默默关闭。生产连接要求 HTTPS；本地测试的 loopback HTTP 是独立的开发测试配置，不作为生产修复方案。

## 7. UI 信息架构

### 7.1 只有两个业务入口

```text
Config Compare
│
├─ 文件比较
├─ Vault 比较
│
└─ 设置 / 帮助
```

左侧栏统一保留；小窗口可以手动折叠。对象或路径选择放在工作区，不增加“项目、服务、发布、事故、工具箱”等导航。

首次进入默认文件比较；不先展示统计 Dashboard。

### 7.2 单一工作区骨架

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Config Compare                  env.js A ↔ B       比较 / 重新比较  导出 │
├────────────┬─────────────────────────────────────────────────────────────┤
│ 文件比较   │ A：old/env.js                  B：new/env.js               │
│ Vault比较  │ 比较对象：env                  比较对象：env               │
│            ├─────────────────────────────────────────────────────────────┤
│            │ 差异 5   全部 7   相同 2   无法比较 0       搜索路径和值   │
│            ├───────────────┬─────────────┬──────────────┬─────────────────┤
│            │ Key           │ A           │ B            │ 状态            │
│            ├───────────────┼─────────────┼──────────────┼─────────────────┤
│            │ b             │ 2           │ <不存在>     │ 仅 A            │

│            │ d             │ <不存在>    │ 4            │ 仅 B            │

│            ├─────────────────────────────────────────────────────────────┤
│ 设置       │ 已比较所选对象 · 7 个结果项 · 完整 · 原文件未修改           │
└────────────┴─────────────────────────────────────────────────────────────┘
```

此示例选中「差异」过滤，因此不在表中显示相同项。计数与第 19 节验收样本一致。

选中字段后，在宽窗口右侧打开检查器；小窗口以底部详情或 sheet 打开，不挤压表格到不可读。

| 编号 | 视图 | 必须覆盖 |

这些主要是同一窗口中的状态与面板，不是十个独立模块。

### 7.4 表格布局硬要求

- A/B 是同一行模型，不是两个互不相关的 ScrollView。
- 表头和内容共享列宽；同一字段左右等高，共享纵向位置。
- Key 列可固定，状态单独一列，不覆盖 B 的值。
- 缺失显示 `<不存在>`；空字符串显示 `""`；未知显示原因，不全用破折号。
- 所有列提供足够的最小宽度；默认 A/B 等宽，可拖动调整。
- 紧凑表格使用有界预览；完整文本在检查器，不无限拉高所有行。
- 搜索/刷新时保持合理的选中项、焦点和滚动锚点。
- 只渲染可见行与必要预取；大值不全部复制进每个 UI cell。
- 嵌套 Key 保留清楚的缩进和可读完整路径，特殊 Key 使用转义形式。
- 状态同时用文字与符号表达，不只依赖红绿颜色。

### 7.5 字段检查器

选中 `port` 时显示：

```text

类型：Number
值：3000
位置：old/env.js 的真实行列号

位置：new/env.js 的真实行列号

说明：数字 3000 与字符串 "3000" 不会被自动视为相同。
```

无“采用 A 写入 B”“同步”“发布”等按钮。

- string/number 的显示和比较状态一致。
- 有未知项时不出现“全部一致”的绿色横幅。
- Vault 来源不出现文件行号；没有网络请求时不出现“已连接”。

- 正常、空、错误、部分成功、长内容、浅/深色、小窗口都审阅。
- 动画用录屏验收，不能拿静态截图声称动效完成。

## 9. 技术架构与选择依据

### 9.1 推荐组合

| 层 | 建议技术 | 责任 |
| --- | --- | --- |
| 窗口与界面 | SwiftUI | 导航、输入、面板、设置、动画 |
| 大表格与源码 | AppKit | 列宽、文本选择、表格复用与细粒度交互 |
| 文件/网络/凭证 | Foundation / Security | 系统授权、只读文件、URLSession、Keychain |
| JS 解析 | Oxc parser + semantic 基础 | 语法树、位置、绑定分析基础 |
| 静态求值与 Diff | Rust | 类型树、保守求值、对齐、差异、搜索索引 |
| Swift/Rust 连接 | UniFFI，P0 验证 | 类型化、粗粒度接口 |
| 重任务隔离 | 按需 XPC worker | 避免异常解析拖死主 UI |
| 轻量配置保存 | App 偏好与少量版本化本地配置 | 布局和明确保存的来源档案 |

SwiftUI 与 AppKit 可组合使用，这是原生界面的基础能力。[S09]

选择 Rust 是为了复用成熟的 JS 解析基础、独立测试比较核心，不因为它“必然更快”。性能必须测量。

### 9.2 FFI 必须先做真实验证

UniFFI 提供 Swift 绑定，但其文档对 Swift 6 / Sendable 等兼容性仍有具体说明；不能仅凭“支持 Swift”就认为严格并发模式下所有接口都可以直接使用。[S11]

P0 必须验证：

- 目标 Xcode、Swift 工具链、Rust、Oxc、UniFFI 的固定版本组合。
- 同步任务接口、错误传播、取消、对象释放和进程中断。
- Swift 严格并发检查，不用大范围 `@unchecked Sendable` 掩盖问题。
- 任意复杂配置值通过版本化 DTO 传输，不把 AST 指针或非稳定内部结构暴露给 UI。
- 失败时可使用窄 C ABI 替代桥接，不降低功能和测试要求，也不新增运行时依赖。

**桥接选择判据：** P0 固定工具链后，用同一份类型化 DTO 验证严格并发编译、值的无损往返、错误传播、取消响应与资源释放。若 UniFFI 在其中一项无法满足要求，且修复仍需靠关闭检查或无依据的大范围 `@unchecked Sendable` 掩盖，则记录失败证据，评估窄 C ABI，并重复同一验收矩阵。生成代码或局部并发适配必须有线程/所有权依据和验证，不将所有 `@unchecked Sendable` 出现都自动判失败。

P0 退出时必须选定一个通过桥接矩阵的方案；不能把两套都失败记作“以后再处理”。worker 崩溃、XPC 连接失效、取消后晚到响应和无响应终止需单独验证，换 FFI 不意味着这些生命周期问题自动解决。

### 9.3 进程结构

```text
Config Compare.app
│
├─ 主 App
│   ├─ SwiftUI / AppKit
│   ├─ 会话状态机
│   ├─ 文件读取与导出授权
│   ├─ VaultReader（仅允许特定只读操作）
│   ├─ 凭证管理
│   └─ 结果呈现
│
└─ CompareWorker.xpc（按需启动）
    ├─ Swift wrapper / UniFFI
    └─ Rust Core
        ├─ env.js parser / static evaluator
        ├─ Vault JSON input adapter
        ├─ Typed Config Tree
        ├─ Diff Engine
        ├─ Search / sort / details
        └─ Report model
```

XPC 是进程通信层，UniFFI 是 worker 内的语言连接层。XPC 的隔离效果取决于实际权限设计，不能仅凭使用 XPC 就宣称安全。[S12]

worker 不接收 Token，不具备业务网络能力，不读取任意源码路径；只处理主 App 按用户授权提交的字节或受限句柄。

### 9.4 用户依然只拿到一个 App

开发者需要构建工具；最终用户不需要。

App 包里包含已经编译好的库和必要 helper，不是让使用者安装 Rust、Node 或 Xcode。一个 `.app` 不等于内部必须只有一个 executable。

不嵌入 Electron，不要求 Tauri，不搭云端比较后端，不装常驻 daemon。

## 10. 数据模型、接口与状态机

### 10.1 类型化模型

以下是设计契约，不是可直接编译的最终实现。

```text
SourceSnapshot
  id
  kind: EnvJs | VaultLiveKv | VaultImportedKv
  label
  selected_scope
  captured_at
  provenance
  completeness
  incomplete_ranges
  root_nodes

ConfigNode
  typed_path_segments
  presence
  knowledge
  value_or_expression
  source_spans
  diagnostics

Value
  Null
  Undefined
  Boolean
  JsNumber
  JsonNumber
  BigInt
  StringCodeUnits
  Object
  Array（含 Hole）

Knowledge
  Known
  Unknown(reason, affected_scope)

DiffRecord
  level: Secret | Field
  path
  side_a_observation
  side_b_observation
  status
  reason
  child_refs
  source_refs

IncompleteRange
  source_id
  relative_scope_or_blocked_root
  reasons
  known_uncovered_paths
  affected_remainder
```

Presence 与 Knowledge 分开：字段是否存在可能已知，但值未知；整个对象形状也可能未知。不要把所有状态塞进一个 nullable value。

每侧 `kind` 与实际输入方式独立保存；离线 `captured_at` 表示导入时间，Vault 实际观测时间、版本及其可信来源放入 provenance，缺少时保持 Unknown。会话保存一对选定根及当前业务模式；不因为 DTO 能描述多种来源就自动开放范围外组合。

### 10.2 路径模型

使用分段类型：对象 Key 与数组下标分开。

显示路径可读，机器导出使用明确转义；不能只把点号字符串当主键。路径包含 `/`、`~`、`.`、方括号、空字符串时有专门测试。

Vault 的来源路径与 secret 内部字段路径也分开保存，不把两个概念串成一个不可还原的字符串。

机器路径由“secret 相对路径（适用时）+ 根下字段分段路径”组成；两者类型分开。显示根名不加入字段主键，`foo` secret 与 `foo/` 目录标记分开表示。

### 10.3 状态机

```text
Empty
  → InputsReady
  → Validating
  → Reading / Parsing
  → Comparing
  → Complete | Partial | Failed | Cancelled
```

输入变化增加 `generation_id`。晚到的旧请求、旧 worker 回调、旧搜索结果不能覆盖新会话。

刷新使用新快照；旧结果可以保留供查看，但必须有“上一轮结果”标记。切换 A/B 不改变来源事实，只改变方向、排序和相应缓存键。

### 10.4 建议接口形状

```text
prepare_inputs(session, source_bytes, selected_roots)
compare(session, generation, comparison_policy)
query_rows(session, generation, filter, search, offset, limit)
get_details(session, generation, row_id)
get_source_excerpt(session, generation, source_ref)
build_report(session, generation, export_scope, value_policy)
cancel(session, generation)
release(session)
```

Vault 网络接口与比较接口分开。Diff Engine 不持有凭证，不自行发 HTTP 请求。

### 10.5 大输入与并发

- Swift 主线程只更新可见 UI，不解析 JS、不排序全部结果。
- worker 保存 AST/类型树，界面只取可见行和选中详情。
- 批量更新 UI，避免每读一个字段触发整页重绘。
- 大文本与搜索结果用明确大小上限；完整值按需读取，不静默截断报告。
- 取消令牌贯穿任务，worker 无响应时可终止并清楚标记任务失败。
- 不使用包含 Secret 内容的普通临时文件来实现大数据 IPC。
- 内存上限包括输入、AST、类型树、索引和桥接复制，不能只测 Rust heap。

### 10.6 原因、错误码与来源观测映射

以下是 v1 的最小映射契约；P0 将其冻结到 DTO 与测试。操作错误码用于阶段失败和恢复，Knowledge 原因用于结果或范围不确定性，来源观测保存取得的事实。多个状态码本身不足以证明来源状态，不能为了填表臆测。

| 情况 | Knowledge / 无法比较原因 | 稳定操作错误码 | 来源观测 |
| --- | --- | --- | --- |
| 动态表达式或未知调用 | UNRESOLVED_EXPRESSION | JS_VALUE_UNRESOLVED | 原表达式位置及受影响范围 |
| 绑定/别名身份未知 | UNKNOWN_OBJECT_IDENTITY | JS_IDENTITY_UNKNOWN | 可确定的绑定与影响范围 |
| 未支持 getter/原型等语义 | UNSUPPORTED_SEMANTICS | JS_SEMANTICS_UNSUPPORTED | 语法类型与位置 |
| JS/JSON 语法错误、JSON 重复 Key | PARSE_ERROR | JS_PARSE_ERROR / JSON_PARSE_ERROR / JSON_DUPLICATE_KEY | 安全的位置诊断，不记录原始值 |
| 已确认凭证失效 / 权限不足 | AUTHENTICATION_FAILED / PERMISSION_DENIED | VAULT_AUTH_FAILED / VAULT_PERMISSION_DENIED | 请求阶段；403 未必能区分失效与无权，不猜测 |
| mount/KV 类型未确认 | PATH_UNCONFIRMED | VAULT_MOUNT_UNCONFIRMED | 可取得的识别依据或失败阶段 |
| 非预期响应 / 输入包装不符 | UNEXPECTED_RESPONSE | VAULT_RESPONSE_INVALID / IMPORT_SCHEMA_INVALID | 响应类型或声明的输入类型 |
| 已删除/销毁或其他无可比较内容 | NO_COMPARABLE_CONTENT | VAULT_CONTENT_UNAVAILABLE | SoftDeleted / Destroyed / ContentUnavailable，具体事实分别保存 |
| 超时、TLS、连接或其他读取失败 | FETCH_FAILED | VAULT_TIMEOUT / VAULT_TLS_FAILED / VAULT_FETCH_FAILED | 失败阶段，不写完整请求/响应 |
| 列举失败、未导入或未扫描范围 | NOT_SCANNED 或实际失败原因 | VAULT_LIST_FAILED / SCOPE_NOT_SCANNED | 阻断根或已知未覆盖路径 |
| 字节、深度、指数、步骤等超限 | RESOURCE_LIMIT | RESOURCE_LIMIT_REACHED | 限制项与受影响范围 |
| 比较期间来源变化 | SOURCE_CHANGED | SOURCE_CHANGED | 已确认的快照/版本信息 |
| 用户取消 / worker 中断 | CANCELLED / NOT_SCANNED | TASK_CANCELLED / WORKER_INTERRUPTED | 已完成部分与中断阶段 |

错误码不新增业务差异类别；若无法建立节点，则关联到阶段错误或 IncompleteRange。UI、报告、适配器和核心共享这份映射；响应里未经证实的状态不转成来源事实。

## 11. 本地数据、凭证与导出

### 11.1 显示策略

配置值按用户要求默认可见；提供一键隐藏，便于分享屏幕。Token 输入仍使用遮罩，显示配置值不代表凭证必须常显。

不宣称可以阻止截图、彻底消除内存副本或保证所有系统层缓存不可见。

### 11.2 保存策略

| 数据 | 默认行为 |
| --- | --- |
| 当前原始文件与配置值 | 内存会话，不自动保存副本 |
| Vault 返回的值 | 内存会话，不自动形成内容历史 |
| Token | 当前会话；用户明确选择后才写 Keychain |
| 来源档案 | 仅用户选择保存的必要字段，无 Token 明文 |
| 窗口/密度/主题 | 可保存本地偏好 |
| 搜索词 | 不持久化，避免保存可能包含的 Secret |
| 诊断日志 | 事件类别、阶段和耗时；排除值、Token、完整请求/响应体 |
| 崩溃附件 | 不自动附加配置、截图或网络响应 |

关闭会话释放内容；不通过普通 App 状态恢复机制自动写出明文 Secret。日志和错误消息也可能包含敏感路径，必须最小化。

Keychain 是建议的系统凭证保存方式；具体访问控制、身份绑定与打包后行为在 P0 和分发测试中验证。[S13]

### 11.3 网络行为

文件模式与离线 Vault 模式对业务网络的请求数必须为 0。

直连使用独立网络会话，配置不落盘缓存、不使用自动 Cookie 登录，不共享浏览器登录态。显式清理请求对象生命周期内的凭证引用，但不作绝对内存清零承诺。

不遥测配置内容，不访问 AI，不嵌入云同步。安装时系统 Gatekeeper 等系统网络行为应与 App 的业务请求分开解释。

### 11.4 导出

报告只服务当前比较，支持 JSON / CSV 两种必要形式，不建设复杂报告平台。

导出前明确：

```text
范围：全部结果 / 当前筛选 / 选中项
内容：只含路径、类型、状态 / 包含真实值
来源：是否包含完整来源标签或使用匿名标签
```

JSON 报告保留 schemaVersion、类型、存在状态、无法比较原因、范围、读取时间和完整性；不能把 Undefined、BigInt、非有限数值等强行塞成普通 JSON 标量造成信息丢失。

CSV 中类型、存在状态、A/B 值单列，正确处理引号和换行；对可能被电子表格解释为公式的内容使用明确的安全导出策略，并提示这不是原始值的字节级镜像。精确值以 JSON 形式保留。

任何导出都不得覆盖当前输入文件。保存时检查规范路径与可获得的文件标识，防止通过别名、符号链接或同名目标误覆盖 A/B。

导出路径由用户选择；未完成写入要清理半成品并显示失败，不把“按钮点击”当导出成功。

## 12. 错误信息与恢复

| 情况 | 应有提示与动作 | 禁止行为 |
| --- | --- | --- |
| 一侧没选文件 | 指出缺哪一侧 | 点击后无反应 |
| JS 语法错误 | 行列号、简短原因、源码定位 | 正则“修复”后当原文成功 |
| 目标对象不存在 | 列出发现的候选对象 | 自动选一个名字相似的对象 |
| 动态表达式 | 原表达式、未解析原因、影响范围 | 相同表达式标 SAME |
| Vault mount 未确认 | 指出未确认，暂停读取 | 换路由猜测并反复请求 |
| Token/权限问题 | 显示失败阶段，允许重新输入 | 要求 root Token |
| TLS/代理问题 | 保留安全诊断与来源 | 自动关闭证书验证 |
| 搜索无结果 | 显示过滤范围与清空入口 | 宣称没有差异 |
| 一侧失败 | 保留已得到内容，总体 Partial | 将另一侧全标 Only A/B |
| 取消 | 显示已取消及已完成范围 | 继续把晚到任务标成功 |
| worker 崩溃 | 说明计算中断，可重新比较 | UI 一并退出或自动发送秘密日志 |
| 导出失败 | 保留当前结果，允许重新选择位置 | 丢失结果或留下看似完整报告 |

所有用户可见错误使用稳定 error code，方便测试与定位；原始服务端响应不原封不动写进日志或弹窗。

## 13. 性能与体验验收目标

以下是待测目标，不是已经达到的成绩。P0 建立基线后，以版本化基准和真实设备结果固化。

| 项目 | 初始目标与测量口径 |
| --- | --- |
| 冷启动 | 参考 M3/24GB，Release 构建到可输入界面 P95 ≤2 秒 |
| 常规配置 | 每侧约 1 万节点、≤5 MiB 的静态输入，文件读入后到首个可操作结果目标 ≤1 秒 |
| 大输入 | 每侧约 10 万节点、≤20 MiB；异步处理、不冻结主线程，记录完整耗时和总内存 |
| 搜索 | 10 万结果项中普通子串查询，索引就绪后 P95 目标 ≤100 ms |
| 滚动 | 60Hz 测试屏以帧时间与长帧记录验收，不只看主观流畅 |
| 取消反馈 | UI 在 100 ms 内反映；停止任务的预算另测且有上限 |
| 空闲 | 没有活跃任务时无定时业务网络请求，无持续动画和后台扫描 |
| 内存 | 初始为 10 万节点基准设总量预算；超预算不得静默丢字段 |
| 多次使用 | 连续比较/清空/替换 100 次，检查句柄、凭证引用和内存增长 |
| 安装体验 | 干净 Mac 无开发环境可打开，核心文件比较离线完成 |

性能报告写明硬件、OS、工具链、输入结构、节点数、字节数、冷/热缓存、Release/Debug、P50/P95。Vault 网络延迟单独统计，不混成“引擎慢/快”。

不拿支持大文件作为取消资源限制的理由，也不为了过性能测试忽略未解析节点。

## 15. 分阶段开发与退出条件

阶段是实现顺序，不是缩减终态。每阶段交付可运行成果，不能只画 UI 或只堆基础设施。

### P0 — 样本、语义、UI 和构建链验证

**交付：** 原始范围清单、脱敏样本、解析支持矩阵、唯一设计系统、Swift→XPC→Rust→Oxc 最小链路、签名试包。

**任务：**

- 用第 19 节合成样本开工，真实样本稍后补入回归库。
- 确认实际 Mac 系统/架构、Vault KV 与 namespace 情况。
- 验证 UniFFI 严格并发、worker 生命周期与取消。
- 验证单个目标 Vault mount 识别与最小读取，不使用生产测试。
- 做文件输入、结果表、检查器、Vault 输入四个关键交互原型。
- 用实际数据检查表格与计数，不沿用旧 SRE 图。

补清契约与上述实验可以同时推进；退出时必须具备以下记录，不能只登记待办：

| 验证项 | P0 必须取得的证据 | 停止/不通过条件 |
| --- | --- | --- |
| 语义与身份 | 版本化契约、预期树及 C19–C22/J06/J09–J13/J21–J22 合成回归输出 | 出现错误 SAME/ONLY，或 Unknown 传播与身份合并规则仍未定版 |
| Swift/XPC/Rust/Oxc 链路 | 固定工具链的最小可运行 App、严格并发编译、DTO 无损往返、错误与取消/释放证据 | 靠关闭检查或无依据的大范围并发声明绕过；没有一个桥接方案通过同一矩阵 |

| Vault 限定读取 | 非生产 KV v1/v2、无 list 权限单 secret、定向识别失败、403/歧义404 的请求记录与预期状态 | 识别失败后猜路由读取、发生未许可请求/写入、错误解释为缺失 |
| 输入与最小界面 | 第 19 节样本闭环；JSON 重复 Key/包装/schema 用例；输入、结果表、详情及 Vault 输入状态证据 | 展示数据与计数不一致、未知提示消失、无真实数据链路 |
| 试包与发布依赖 | 最小 App 试包、实际签名类型、包内依赖与链接路径检查；架构/最低系统及正式签名、公证依赖清单 | 功能依赖用户安装开发工具；把开发签名试包称为正式 Gatekeeper/发行验证 |

**退出条件：** 以上 P0 验证项通过；比较策略、输入 schema、对象身份、错误映射、资源预算与桥接选择均有书面版本和对应证据；未知兼容项明确影响范围与后续阶段。非阻断的真实设备信息可以保留待确认，但不能以“有清单”替代核心链路或语义验证。未验证的目标系统或 Vault 部署不写入已支持矩阵。

### P1 — 文件比较纵向闭环

**交付：** 选择两份 env.js → 识别对象 → 比较 → 详情 → 复制。

**任务：** 类型树、五类可比较结果与无法比较、独立完整性记录、基本静态求值、来源位置、真实数据表、搜索过滤、取消。

**退出条件：** 原始场景和 C/J 核心测试通过；乱序无误报；env/devConfig/导出范围正确；不会执行脚本；错误不会冒充完整成功。

### P2 — env.js 深度与结果 UI 完整性

**交付：** 已知引用、展开、别名、导出重绑定、长值和源码视图；完整动画与可访问性路径。

**任务：** 保守未知传播、特殊值、精度、重复 Key、边界性能、资源上限、所有页面状态。

**退出条件：** 完整支持矩阵与限制说明；对应 J/C 测试通过；UI 的全部/差异/未知计数一致；无假运行时结论。

### P3 — Vault 两种输入闭环

**交付：** Vault 已有内容比较 + 手动 KV 只读比较；单 secret、明确清单、受限目录。

**任务：** Token 来源隔离、KV 路由、targeted mount 确认、网络白名单、权限与完整性、取消/重试、版本来源标签。

**退出条件：** V 用例通过；文件/离线模式零业务网络请求；无任意 engine 读取、无写入端点、无后台连接；真实受支持测试部署通过。

### P4 — 完整使用体验与输出

**交付：** 复制、JSON/CSV 报告、轻量来源档案、设置、隐私处理、全页错误恢复。

**任务：** 导出范围、值策略、类型无损、输入保护、凭证选择保存、数据生命周期、大输入调优。

**退出条件：** U/C 对应测试通过；报告与界面同一结果；不保存意外明文副本；所有 UI 状态有截图和录屏证据。

### P5 — 发布验证与交付

**交付：** 可分发 `.app/.dmg`、用户手册、支持矩阵、测试与性能证据。

**任务：** 固定依赖、许可证清单、签名/公证、目标架构、干净 Mac 首次打开、离线文件流程、升级/卸载检查、双 reviewer 复核。

**退出条件：** 发布门槛全部满足；关键失败为0；未执行测试不被写成通过；外部访问与环境限制如实列出。

动画、签名和依赖验证从 P0 开始；P5 是最终收敛，不是最后才考虑它们。

**分阶段证据边界：**

| 阶段 | 本阶段必须验证 | 保留给后续阶段的正式门槛 |

## 17. AI 开发与评审执行规则

本节可直接提供给本地开发 AI 作为执行约束。

### 17.1 开发范围

> 只实现本文定义的 env.js↔env.js 与 Vault↔Vault 配置比较。不要主动加入 SRE 平台、日志工具、混合比较、同步、写入、AI 或发布功能。辅助设置与导出必须服务于当前比较。
>
> 先读样本与测试，再实现纵向闭环。遇到真实语义或访问限制，记录证据并提出需要确认的具体问题，不通过猜测、关闭安全检查或隐藏诊断绕过。
>
> 不因成本、时间、难度降低比较正确性、界面质量和测试要求；也不把“追求强大”当成扩大范围的授权。

### 17.2 任务记录格式

每个任务包含：

```text
任务 ID
对应需求 Rxx
输入 / 输出
依赖任务
实现位置
验收测试 ID
运行命令与环境
测试结果与证据

review 状态
```

一个阶段只有截图没有可运行数据链路，不算交付。

### 17.3 双评审

采用 Claude Code 与 DeepSeek 双 reviewer 的工作方式，但评审记录必须区分真实运行与静态阅读。

| Reviewer 重点 | 检查内容 |
| --- | --- |
| 正确性评审 | 静态求值、缺失/未知、精度、并发、取消、Vault 路由与完整性 |
| 体验与安全评审 | 使用流程、UI 一致性、动效、可访问性、凭证/日志/分发、范围外功能 |

两者都看同一 commit 与同一证据清单，不靠角色分工跳过交叉复查。

仅讨论未提交文档时，用冻结文件的 SHA-256 及版本绑定意见，并验证两侧实际阅读内容一致，不虚构 commit。文档修改后重新计算哈希；上一版本的讨论或同意不自动成为新版本接受。独立初审与收到其他 reviewer 意见后的讨论分别标注；缺失、超时或截断输出均不是通过。

Claude Code 超时记为 TIMEOUT/INCOMPLETE。分块审查、限制单次输入、保存进度并做有界重试；持续阻塞需报告，不无限重跑，也不自动视为 PASS。

Reviewer 提出问题 → 修复 → 相关回归 → 更新证据 → 复审。不能仅改一句说明就消除实际错误。

双 reviewer 同意也不等于零 bug；最终还需要自动测试、人工走查和真实分发设备验证。

## 18. macOS 构建与分发

```text

    ↓
拖入 Applications
    ↓
打开 Config Compare.app
    ↓
```

不让用户运行 chmod，不需要终端安装依赖，不通过调用 `/usr/local/bin`、`/opt/homebrew/bin`、nvm 或 shell profile 获取功能。

### 18.2 架构和系统支持

目标支持 Apple Silicon；若使用者包含 Intel Mac，同时交付经验证的 x86_64 构建。优先验证一个 Universal 分发包；如果固定工具链限制不能满足，明确发布两个对应架构包，而不是悄悄依赖 Rosetta。

最低 macOS 版本由真实设备清单、UI API 与所选工具链共同确定。不能在未构建测试前宣称所有 Mac 都能运行。

文件与依赖都在 App 包内或使用受支持系统框架；检查所有 dylib 的实际链接路径，避免开发机 Homebrew 路径泄漏到发布包。

### 18.3 签名和安装安全

站外分发使用 Developer ID、正确的嵌套代码签名、Hardened Runtime、公证与票据附加。Apple 官方分发文档说明了相应机制及 notarytool/stapler 流程。[S14]

不能把关闭 Gatekeeper、手动删除 quarantine 或要求管理员降低安全策略写成正常安装教程。

签名、公证不能绕过企业设备管理策略，也不意味着系统不会显示正常的首次打开确认。

### 18.4 发布流水线

```text
锁定工具链与依赖
 → 授权/许可证检查
 → 核心与适配器测试
 → 各目标架构构建
 → UI/安全/性能测试
 → 链接与包内依赖检查
 → 正确签名
 → 公证并附加票据
 → DMG 完整性检查
 → 干净设备安装验证
 → 发布包、校验值、说明和证据归档
```

自动更新服务不是本次必要模块。先把正式签名包的获取、替换安装和版本说明做好，不引入额外后台检查。

## 19. 可直接开工的验收样本

### 19.1 文件 A

```js
var devConfig = {
  DEBUG: true,
};

var env = {
  a: 1,
  b: 2,
  c: 3,
  port: 3000,
  redis: {
    host: "cache-a",
    port: 6379,
  },
};

module.exports = env;
```

### 19.2 文件 B

```js
var devConfig = {
  DEBUG: false,
};

var env = {
  redis: {
    port: 6379,
    host: "cache-b",
  },
  port: "3000",
  c: 30,
  a: 1,
  d: 4,
};

module.exports = env;
```

### 19.3 env 对象的预期结果

| 路径 | A | B | 结果 |
| --- | --- | --- | --- |
| env.a | Number: 1 | Number: 1 | SAME |
| env.b | Number: 2 | 不存在 | ONLY_A |
| env.c | Number: 3 | Number: 30 | VALUE_CHANGED |
| env.d | 不存在 | Number: 4 | ONLY_B |
| env.port | Number: 3000 | String: "3000" | TYPE_CHANGED |
| env.redis.host | String: "cache-a" | String: "cache-b" | VALUE_CHANGED |
| env.redis.port | Number: 6379 | Number: 6379 | SAME |

摘要：7 个结果项；相同 2；值变化 2；类型变化 1；仅 A 1；仅 B 1；无法比较 0。

`devConfig.DEBUG` 在 devConfig 对象范围内另计一项值变化。选择最终导出模式时，此示例与 env 结果相同；不能因此假设所有输入都如此。

### 19.4 只改排序的样本

```js
// A
var env = { a: 1, c: 3 };
module.exports = env;

// B
var env = { c: 3, a: 1 };
module.exports = env;
```

预期：两个字段相同，差异 0，完整。

### 19.5 必须失败得正确的样本

```js
// 两边都一样写，并不意味着运行时值相同
var env = {
  HOST: getHost(),
  TOKEN: process.env.API_TOKEN,
};
module.exports = env;
```

预期：两项无法比较，显示表达式与原因；不得出现“全部配置一致”。

### 19.6 Vault 集成样本设计

使用临时测试 Vault，分别建立受支持的 KV v1/v2 来源，写入与 env 示例等价的两份 JSON 数据作为测试夹具。

另建测试身份：只读指定 secret、可列举但部分不可读、无 list 权限。夹具准备属于测试设施，不包含在 App 功能中。

测试以下结果：字段差异与文件样本一致；v2 metadata 不进入业务差异；无权限项保持未知；离线导入相同数据得到相同结构结果。
